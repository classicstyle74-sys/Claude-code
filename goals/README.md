# goals/ の地図

Addness のゴールの代わりに、仕事の単位（ゴール）を1つ1ファイルで置く場所。ここが仕事の状態・決めたこと・分かったことの正本になる。

## ファイルの置き方

- 1ゴール = 1ファイル（`goals/<英小文字とハイフンの名前>.md`）。
- 子ゴールが増えるゴールは、フォルダにして `index.md` を親、ほかのファイルを子にする（例：`goals/mikami-way/index.md` と `goals/mikami-way/02-workspace.md`）。
- 終わったゴールは消さず、`status: done` にしてそのまま置く。領域ごと終わったら `archive/` へ移す。

## 1ファイルの形

`goals/_template.md` をコピーして使う。先頭の設定（frontmatter）の意味：

| 項目 | 意味 | 値の例 |
| --- | --- | --- |
| `title` | ゴールの名前 | 作業場を作る |
| `status` | 今の状態 | `todo`（未着手）／`doing`（進行中）／`waiting`（返事待ち）／`done`（完了） |
| `owner` | 担当 | classicstyle74 |
| `today` | 今日のToDoか | `true` ／ `false` |
| `due` | 期限（あれば） | 2026-10-01 |
| `parent` | 親ゴールのファイル（あれば） | goals/mikami-way/index.md |

「今日のToDo」は、`status` が `done` 以外で `today: true`、または `due` が今日以前のゴール。探し方は `grep -l "today: true" -r goals/` など。

## 本文の節

- **理想** … 終わった時にどうなっていればよいか
- **現状** … 今どうなっているか
- **ノート** … 何をするか・決めたことと理由・分かったこと・参照データ・成果物の場所
- **待ち** … 人に聞いていて返事を待っていること（誰に・何を・いつ）
- **作業記録** … 日付と時刻つきで、やったことを足していく

## このフォルダで作業する時のコツ

- 完了（`status: done`）のゴールには書き込まない。同じテーマの生きているゴールに書くか、新しいゴールを作る。
- 本文は短くまとめ直さない。次に開く人やAIが文脈を取り戻す場所なので、決めたことと理由をしっかり残す。
